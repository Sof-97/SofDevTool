# Domain docs

This repository uses a single context: `CONTEXT.md` at the root and ADRs in `docs/adr/`.

## Before exploring

- Read root `CONTEXT.md` for the project's domain vocabulary.
- Read ADRs in `docs/adr/` that concern the area being explored.
- If `docs/adr/` does not exist, proceed; create decisions there when they are resolved.

## Vocabulary and decisions

Use the terms defined in `CONTEXT.md` in issues, specs, proposals, and tests. If a needed term is missing, revisit the wording or record the gap for domain modeling. Surface any conflict with an existing ADR explicitly.
